# Status 流转

仅处理用户明确指定的一个目标 Status。沿 `SKILL.md` 的解析规则先得到唯一 Work Item ID；Number 搜索结果集合不能成为写入目标。

## 读取与解析

1. 路径级能力门禁通过后，调用 `get_work_item` 读取当前 Work Item。使用返回的项目 ID、原始类型、当前 Status 显示名与 ID；关键字段缺失时停止，不推断。
2. 按运行时 schema，把 organization ID、当前 Work Item 的项目 ID 和原始类型传给 `get_work_item_workflow`。每次准备流转都重新读取当前 Work Item 与工作流，不依赖之前对话中的旧值，也不硬编码 Status 名称或 ID。
3. 只在该工作流返回的 Status 候选中，以显示名与用户给出的目标 Status 做完整匹配。不得使用模糊、前缀、别名或跨字段匹配。
4. 恰好一个匹配时采用该候选的 Status ID。零匹配或多个匹配时停止，并逐项列出工作流返回的每一个候选显示名及 ID，包括与目标不同的候选；只列同名匹配项不算完成。分别说明目标未出现在候选中或目标显示名不唯一。
5. 通过 MCP 的当前身份能力读取实际 OAuth 操作身份。身份无法确定时停止，不提交更新。

## 预览与执行

普通请求先输出业务预览，包含 Work Item ID 与 Number（若返回）、标题、当前 Status、唯一目标 Status 和实际操作身份；本轮停在预览，不调用 `update_work_item`。用户随后确认时，重新执行上方读取与解析。

当本次请求明确包含“立即执行”“直接修改”“无需确认”或同等明确含义时，可跳过业务预览并继续提交。这个标记只跳过 skill 业务预览；正常调用 MCP 写工具，让宿主审批与云效权限继续生效，不把用户措辞描述为安全审批。

提交时只调用一次 `update_work_item`，按运行时 schema 传入唯一 Work Item ID 和解析后的 Status ID。负载只表达 Status 变更，不添加其他字段，也不把候选集合转为批量更新。

## 结果验证

- 写工具明确返回业务拒绝时，保留云效原始业务信息并归入最具体的类别：**工作流限制**、**角色限制**、**无权限**或**必填字段卡点**。下一步必须具体对应错误：工作流限制提示允许的中间 Status 或联系工作流维护者；角色限制提示授予返回信息点名的角色或改由具备角色的身份执行；权限不足提示授予当前 OAuth 身份更新权限；必填字段卡点提示补齐返回信息点名的字段。不声称候选存在就代表流转合法，也不自动重试。
- 写工具报告成功后，重新调用 `get_work_item`。回读包含 Status ID 时，只以该 ID 与目标候选 ID 的完整相等作为成功依据；同名但 ID 不同必须报告**结果不确定**。回读缺少 Status ID 时，才允许用显示名完整相等兜底，并明确说明 ID 未提供。ID 与显示名同时返回但彼此矛盾时也报告**结果不确定**。验证成功后报告 Work Item、原 Status、观察到的最终 Status 和实际操作身份。可以调用 `list_workitem_activities` 补强证据，但活动不能替代 Work Item 回读。
- 写工具出现超时、断连或其他传输结果不明确时，先回读同一个 Work Item。若观察到目标 Status，报告已验证成功；若回读失败、仍为原 Status 或出现其他 Status，报告**结果不确定**及实际观察值并停止。
- 每次执行最多一次 `update_work_item`。结果不明确、验证失败和业务拒绝都以停止为完成条件。
