# big-picture

帮助用户先确定总体方向、主要边界和主流程，再把共识交给后续细化。默认在会话中展示总体图并逐项讨论；最终产物是交接包。

## 讨论的层级

判断一个问题的粒度：**它的答案是否会改变总体方向、主要边界或主流程？** 按影响判断，不按是否涉及技术判断。

| 层级 | 讨论内容 |
| --- | --- |
| 目标 | 解决什么问题、为谁服务、成功是什么、范围与关键约束 |
| 结构 | 主要组成、职责与边界、协作关系、主流程、阶段和关键取舍 |
| 待细化 | 接口字段、表结构、具体业务规则、参数、代码和逐项实施任务 |

## 建立总体草图

1. 读取用户提供及直接相关的背景。对已有系统或流程，先弄清现状、约束和需要改变的边界，再提出调整。资料无法取得时说明缺口，将依赖它的判断标为假设。
2. 尽早给出目标概括和总体草图。目标不足以画图时，先问一个目标层问题；不要把细节问卷作为画图的前置条件。
3. 区分已知事实、你的建议和待验证假设。用户确认建议后才记为已确认决策；沉默、未回答和局部认可都不等于整体确认。

在当前对话中维护：目标与边界、当前主图、关键决策及其状态、假设、未决宏观问题、待细化问题。这些信息依据会话上下文维护，不需要数据库或后台服务。每轮只展示有变化或需要确认的部分。

## 每轮推进一个宏观决策

选择当前最影响总体方向的未决问题，说明建议、理由及接受的代价，再提出一个关键问题。只有路线存在实质差异时，才比较两到三个方案。

根据用户输入处理：

| 输入 | 下一步 |
| --- | --- |
| 改变目标、主要边界或主流程 | 说明受影响的决策，讨论相应宏观选择；同步更新主图及决策状态 |
| 普通细节追问 | 简短记录为待细化问题，回到当前宏观决策；不替用户先定字段、枚举、次数等答案 |
| 细节暴露总体风险或约束 | 说明它会改变哪条边界或流程，只讨论对应的总体选择；具体参数继续留待细化 |
| 明确要求现在进入细化、提前交接或结束总体讨论 | 先按下文“确认与交接”的标准处理同条消息里的确认，再按当前状态输出交接包并停止 |
| 只要求暂停 | 简短标明停在哪个问题，等待用户继续，保留当前决策状态 |

普通细节追问本身不表示退出。时间紧迫或某个局部获得认可，也不表示其余总体方案已经通过。用户意图确实不清楚时，只确认是否要结束总体讨论。

例如，讨论需求交付流程时，用户问“优先级字段用 P0/P1/P2 吗”：记入待细化，继续确认谁有权插单以及如何处理既有交付承诺。若用户补充“任何人都能把需求标成最高级并直接插单”，则提升为决策权与插单通道的总体问题，枚举值仍留待细化。

## 图形表达

默认直接在会话里输出 Mermaid 代码块，跟随用户语言，中文场景使用中文短标签：

- 软件架构：系统边界、主要组成及依赖关系。
- 产品或业务流程：角色、主要阶段及流转关系。
- 非技术工作方案：阶段、里程碑及依赖关系。

主图通常包含 3–7 个主要单元，这是默认尺度而非硬限制。复杂主题先聚合；主图确实无法表达关键流转时，再补一张主流程图。同一张图保持同一抽象层级，箭头说明实际关系，并让系统内外边界可辨。

优先使用简单的 `flowchart` 语法、稳定的节点标识和带引号的标签，避免把段落或实现细节塞入节点。方案变化时给出更新后的完整主图，简短说明变化，保持图与文字一致。无法渲染时补充等价的文字关系图并说明情况，不声称已验证显示效果。

## 确认与交接

以整体确认结束时，展示当前完整主图及关键决策，让用户对总体方案作明确确认。确认对象包括目标与边界、主要组成与职责、主流程和关键取舍。尚未解决的宏观问题应继续讨论，或由用户明确接受为假设；提前退出时保留为未决项。

明确确认已经针对当前完整方案作出时，直接交接，不重复索要确认。只认可某个局部时，更新该项状态，继续其余宏观问题。方案发生实质改变后，标明哪些原确认需要重新讨论。

交接包首先标明状态：**已整体确认**，或 **阶段交接，尚未整体确认**。然后填入以下实际内容：

1. **目标与边界**：服务对象、预期结果、包含与不包含的范围、关键约束。
2. **当前主图**：确认后的主图；提前退出时为当前草图，明确未决部分，并附简短说明。
3. **关键决策**：各项状态、理由和接受的代价。用户未认可的建议保留为建议。
4. **假设与重开条件**：依赖的假设，以及什么变化需要重新讨论哪项总体决策；提前退出时也列出未决宏观问题。
5. **待细化问题**：按主要组成或阶段分组，只记录问题，不提前生成实现方案或实施任务。
6. **交接提示词**：可直接复制，包含当前方案和上述状态的引用，要求继承已确认决策、优先细化待办；如发现冲突，指出需要重开的总体决策。交给新任务时，提示用户一并带上完整交接包，使引用可解析。

默认只在会话中交付。用户明确要求保存交接包时，按指定位置及适用仓库规则保存。仅在当前环境确实提供相应技能时，才可在提示词中建议其入口；否则使用通用的“继续需求细化”提示词。

**输出交接包后停止。** 后续技能由用户显式启动；本技能不自动调用其他技能、编写实现计划或开始实现。
