# big-picture 实现计划

> 执行方式：当前任务内联实现；使用 writing-skills 的独立对话场景验证行为。

**目标：** 创建可显式调用的“先定大框架”技能，先形成总体方案，再输出交接包并停止。

**规格依据：** 本任务承接的 big-picture 设计讨论及用户“帮我实现”的实施授权。

**工作区：** 沿用 `codex/add-big-picture-skill`；起始分支及最终合并目标为 `master`。

## 文件与约束

- `skills/big-picture/SKILL.md`：总体讨论、图形表达、确认及阶段交接规则。
- `skills/big-picture/agents/openai.yaml`：中文展示信息、示例调用及显式调用策略。
- 技能目录仅包含以上两个文件；不增加脚本、插件或后台状态。
- 源文件保留在任务 worktree 的 `skills` 目录，以软链接安装到 Codex。
- 讨论覆盖新系统、现有系统改造、产品或业务流程、非技术工作方案。
- 默认只在会话输出；用户明确要求保存时才写文档。
- 原始资料中的建议、事实、假设、局部确认和整体确认分别处理。
- 普通细节记录为问题；影响总体方向、边界、主流程时提升为宏观决策。
- 整体明确确认后交接；用户也可以提前退出，交接时保留未决状态。
- 后续技能由用户显式启动；不自动进入实现或调用下游技能。
- 不合并、推送或发布，直到用户明确授权对应动作。

## 验证方式

行为验证使用隔离的子代理上下文，输入真实需求及必要背景，检查实际回复，不以匹配标题代替行为判断。保留测试输入、回复及结论作为本任务的验证记录。

结构验证优先使用 skill-creator 的 `quick_validate.py`；运行时缺少 PyYAML 时使用已有 YAML 解析器做等价检查，不改全局依赖。安装时拒绝覆盖已有普通文件、目录或不同目标的链接。

图形检查同时关注图的可读性、抽象层级、边界及箭头语义。后续若修改技能，仅对受影响场景补验。

- 带技能场景：业务流程、现有预约系统改造、社区活动规划、新知识问答系统、整体确认与退出同句、局部确认后提前退出。共六组、十三轮实际回复。
